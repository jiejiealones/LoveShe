# v0.1.0 架构与记忆

浏览器界面 → 本机 HTTP 服务 → 应用服务 → SQLite / 模型适配器 / 可选 WeFlow。

| 模块 | 职责 |
| --- | --- |
| `server.py` | 回环地址服务、请求认证、预览确认、后台任务 |
| `service.py` / `core.py` | 联系人、导入去重、统计、咨询、回复、反馈、模型调用 |
| `config.py` / `configure.py` | 本机配置及环境变量覆盖，不向浏览器返回密钥 |
| `automation.py` | 可选微信轮询、每日记忆整理、失败退避 |
| `memory_engine.py` | 日期区间、批次续跑、记忆合并、证据范围校验 |
| `rolling_summary.py` | 人物画像、关系变化、沟通模式、待确认事项的版本化摘要 |
| `adapters.py` | WeFlow 读取与未来读屏、悬浮窗接入约定 |

## 更新闭环

上次完整检查点到今天（含首尾日期） → 补齐聊天 → 冻结消息列表 → 连续分批整理 → 保存记忆与摘要 → 全部成功后推进日期。按联系人隔离；一次失败不推进该批进度。当前每批最多 160 条 / 16000 字原文，另含相关记忆、最多 4 轮咨询与 10 条反馈。

咨询和回复默认召回该联系人的有效摘要、相关记忆与最新消息之前 14 天内最多 120 条近期原文，并包含覆盖范围信息；不代表每次阅读所有历史。回复入口无需提问，生成不同意图的草稿；咨询入口支持问题和追问。

手工纠错、删除和修改档案会提升上下文版本，让旧摘要和追问链失效，防止旧解释继续参与回答。SQLite 是主存储，`contacts/<id>/MEMORY.md`、`memory_summary.md`、`memory_index.md` 和 `profile.json` 为投影文件；直接编辑文件不会修改数据库。

## 边界

静态资源本地提供，服务只监听 `127.0.0.1`，请求检查会话令牌与来源；令牌防护不能抵御已控制本机账户的程序。读屏、悬浮窗尚未实现；后续接入应复用联系人确认、导入审计与模型授权，不自行绕过这些流程。
